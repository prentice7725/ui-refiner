# Refine 벤치마크: unslop 비교, 2026-11-11

[unslop](https://github.com/heydamir/unslop)(Damir Sokolovsky, CC BY 4.0)은 AI가 만든 화면을 9단계 패스로 다듬는 스킬입니다. 낱장 평가에서 `/ui-refine`이 단순 요청에 지는 문제([11회차](REFINE_BENCHMARK_2026-11-08.md))에 도움이 되는지 보려고, 같은 페이지에 세 방식을 돌려 비교했습니다.

**결론:** unslop은 낱장에서도 세트에서도 `/ui-refine`을 이기지 못했습니다. 통째로 따라 할 방식은 아니고, 방향을 제품에서 끌어내는 부분만 참고할 만합니다.

## 방법

1. **원본.** 헤드리스 Claude Code(`claude -p`, Opus 5.5, 스킬·플러그인·MCP·설정 없음)가 한 줄 프롬프트로 단일 파일 페이지 8개를 새로 만들었습니다. 이전 회차의 원본은 저장소에 없어서 같은 주제로 다시 만들었습니다. 주제는 팀 협업 도구, 가계부 앱, 치과, 푸드뱅크(영어), IT 채용, 내과 클리닉(일본어), 자산관리 앱, 물류(한국어)입니다. 프롬프트는 [`scripts/refine-bench/prompts.tsv`](../scripts/refine-bench/prompts.tsv)에 있습니다.
2. **고치기.** 같은 원본에서 세 방식으로 한 번씩 고쳤습니다.
   - **단순 요청:** "Make this page look less AI-generated. Edit index.html in place." 도구는 읽기·쓰기만.
   - **`/ui-refine` 0.7.0:** 명령 본문과 스킬, 마무리 게이트(Stop 훅), `Bash(node:*)` 허용. 사람이 없으므로 방향은 스스로 고르게 했습니다. 8페이지를 순서대로 돌려 선택 기록을 공유했습니다.
   - **unslop:** `SKILL.md`와 참고 문서를 읽고 따르게 했습니다. 사람이 없으므로 방향 확인 단계는 건너뛰게 했고, 이미지 생성 도구와 스토리 영상은 쓰지 않았습니다. `Bash(node:*)` 허용.
3. **평가.** 헤드리스 Claude(Opus 5.5)가 이름을 가린 스크린샷을 봤습니다.
   - 페이지 평가: 같은 페이지의 네 버전(첫 화면과 전체 페이지)에 점수를 주고 순위를 매깁니다. 8회.
   - 세트 평가: 한 방식의 8페이지 첫 화면을 한 장에 모아, 서로 얼마나 닮았는지(1–10)와 순위를 매깁니다. 2회.
4. **측정.** 모든 버전에 `ui-refiner scan`을 돌렸고, 원본에서 `keep record`를 한 뒤 각 버전에 `keep check`를 돌렸습니다.

하네스는 [`scripts/refine-bench/`](../scripts/refine-bench/README.md)에, 네 버전의 HTML과 평가 원문은 [`docs/refine-bench-2026-11-11/`](refine-bench-2026-11-11/)에 있습니다.

## 읽는 법

- **unslop은 보수적입니다.** 원본의 구조(왼쪽 제목 + 오른쪽 패널)와 팔레트를 유지하고 간격, 굵기, 배지 같은 디테일을 정돈합니다. 평가는 치과 페이지를 "원본을 깔끔하게 고친 버전이지만 여전히 흔한 SaaS 카드 구성"이라고 적었습니다.
- **unslop은 세트로 보면 원본과 비슷합니다.** 유사도 7–8. 세트 평가가 짚은 습관은 미색 바탕, 세리프 제목, 왼쪽 제목 옆에 떠 있는 카드, 채운 버튼과 테두리 버튼 한 쌍입니다.
- **unslop은 숫자를 바꿉니다.** 8페이지 중 7페이지에서 원본 수치가 1–6개 사라지거나 바뀌었습니다. unslop은 확인할 수 없는 주장을 지우라고 지시하므로 일부는 의도된 삭제일 수 있습니다. 하나씩 확인하지는 않았습니다.
- **`/ui-refine`은 세트에서 두 번 모두 1위입니다.** 유사도 3. 평가가 여전히 짚은 습관은 히어로의 운영 데이터 패널, 버튼 한 쌍, 히어로 아래 작은 글씨 줄, 가는 선 카드입니다.
- **`/ui-refine`과 단순 요청의 낱장 차이는 0.5입니다.** 이전 회차에서 0.6 미만은 오차로 봤습니다. 11회차(3.5 대 2.0)보다 좁지만 페이지와 비교 대상 수가 달라 격차가 줄었다고 말할 수는 없습니다.
- **`/ui-refine`이 진 페이지의 평가 메모:**
  - en-dental: "굵은 컨덴스드 대문자와 검정·빨강 간판 느낌이 '부드러운' 가족 치과에 거칠다."
  - ja-recruit: "5열 구인 보드의 카드가 비좁고, 히어로 문구 줄바꿈이 어색하다."
  - en-saas: "차분하게 잘 묶여 있지만 서체가 평범하고 가운데 정렬 히어로가 익숙한 템플릿이다."
- **`/ui-refine`이 이긴 페이지**는 푸드뱅크(지금 문이 열려 있는지), 내과(이번 주 진료 시간과 약도), 물류(오늘 출고 화면)로, 고유 요소가 방문자가 찾는 정보와 맞아떨어진 경우입니다.
- 평가는 미색 바탕과 세리프 제목에 여전히 후합니다. 단순 요청이 1위를 한 5페이지 대부분이 그 모습입니다.

## 다음에 시험할 것

unslop에서 가져올 만한 것은 측정이 아니라 방향을 정하는 방식입니다.

1. **배정을 제품의 성격에 맞는 후보 안으로 좁히기.** unslop은 방향을 다섯 줄(제품, 성격, 세계, 순간, 시그니처)로 쓰고, 색조·강조색·서체를 제품이 속한 "세계"에서 고릅니다. `directions deal`은 서체와 강조색을 제품과 무관하게 배정합니다. 치과 페이지의 "거칠다"는 지적이 여기서 나옵니다. 페이지 성격(예: 차분함, 기술적, 따뜻함)을 먼저 정하고, 그 성격에 맞는 서체 조합과 색 계열 안에서만 배정하는 방식을 시험합니다. 다양성은 구조와, 성격 안의 선택으로 유지합니다.
2. **제품 화면은 "한 줄 소개를 증명하는 한 장면"만.** unslop은 앱 전체가 아니라 예약된 슬롯 하나, 댓글 달린 diff 하나를 보여 주라고 합니다. 세트 평가가 계속 짚는 "히어로의 운영 데이터 패널"과 ja-recruit의 비좁은 5열 보드에 대응합니다.
3. **이름 바꿔 보기 점검.** 제품 이름을 다른 것으로 바꿔도 화면이 맞으면 방향을 더 민다. 비용이 거의 없는 마지막 점검입니다.
4. **슬롭 정도에 따른 분기.** unslop은 심하면 전체 과정, 가벼우면 기존 브랜드를 유지하는 다듬기, 없으면 손대지 않습니다. `/ui-refine`은 항상 세 방향을 새로 만듭니다.

우선순위를 낮춘 것: 간격 4px 격자, 제목 굵기 400–500 같은 수치 패스. unslop이 이것을 하고도 타이포 점수가 `/ui-refine`과 같았습니다(7.0).

가져오지 않을 것:
- **unslop의 토큰.** 권장 서체에 `directions deal`이 맨 뒤로 미루는 Fraunces, Bricolage Grotesque가 있고, 따뜻한 바탕 `#f7f4ee`는 스캔이 AI 기본값으로 잡는 미색입니다.
- **문구.** CC BY 4.0이라 문구나 표를 옮기면 출처 표기가 필요합니다. 아이디어만 다시 씁니다.

## 한계

- **`/ui-refine`이 사진 없이 돌았습니다.** 위키미디어가 실행 환경(클라우드 IP)의 검색을 429로 거절해서, 서비스 4페이지(치과, 푸드뱅크, 채용, 내과)가 대체 사진 대신 코드로 만든 화면을 썼습니다. 11회차 조건과 다릅니다. 로컬에서 다시 돌리면 이 부분이 달라질 수 있습니다.
- 원본을 새로 만들었으므로 1–11회차 숫자와 직접 비교되지 않습니다. 사람 사이트 대조군이 없습니다.
- unslop은 이미지 생성 도구 없이, 방향 확인 없이 돌았습니다. 저자가 가장 강하다고 하는 "생성한 장면이 히어로 전체를 채우는" 구성은 시험되지 않았습니다.
- 허용 도구가 `Bash(node:*)`뿐이라 묶은 명령과 `python3`, `sed`가 페이지마다 2–9번 거부됐습니다. 세 방식 모두 같은 조건입니다.
- 8페이지, 방식마다 1회 실행, Claude가 Claude의 결과를 평가했습니다.
- 스크린샷은 커밋하지 않았습니다. `scripts/refine-bench/shots.cjs`로 다시 찍을 수 있습니다.
