## クイックスタート

必要環境：Node.js 22.18以上、npm、Git。

```sh
git clone https://github.com/prentice7725/ui-refiner && cd ui-refiner
npm ci && npx playwright install chromium
npm link                                   # 任意：どこからでも`ui-refiner`で実行できるようにする

ui-refiner scan your-site.example          # 公開中のページを点検
ui-refiner scan localhost:5173             # 開発サーバー。直したあと同じコマンドを再実行すると変化が分かる
ui-refiner keep record index.html                                  # リファイン前にリンク・フォーム・数値を記録
ui-refiner directions deal refine-directions --kind service --tone calm --lang ja   # 案ごとにヒーロー構成・地色・色の系統を割り当て、避ける書体を列挙
ui-refiner directions refine-directions     # デザイン案（.html）を並べて比較し、1つ選ぶ
ui-refiner directions record refine-directions --pick B                # 選んだ方針を記録（別のクライアントには別の方針）
ui-refiner photos "dentist chair" --out assets/stand-in             # 実際の写真が届くまでの出典付き仮写真（Wikimedia Commons）
ui-refiner directions verify refine-directions index.html             # 仕上がりが選んだ構成を保っているか確認
ui-refiner keep check index.html                                   # リファイン後のページで一つでも失われたら exit 1
```

これだけです。`scan`はURL、ホスト名、ローカルの`.html`ファイルを受け付け、設定は不要で、対象プロジェクトを変更しません。`npm link`をしていない場合は`node bin/ui-refiner.mjs scan …`で実行します。

- **レポートの言語**はページに合わせます。日本語ページは日本語、韓国語ページは韓国語、それ以外は英語です。常に同じ言語にしたい場合は`UI_REFINER_LANG=ja`（または`ko`、`en`）を設定し、1回だけ変えるなら`--lang`を使います。ブラウザのロケールはホストに合わせます（`.jp` → `ja-JP`、`.kr` → `ko-KR`）。`--locale`で変更できます。
- **再スキャンすると自動で比較します。** 出力フォルダーに同じページの前回スキャンがあれば、新しいレポートの先頭に前後比較が付きます。比較しない場合は`--no-compare`、別フォルダーのスキャンと比べる場合は`--compare <フォルダー>`を使います。
- `--source src`でソースの静的検査を追加、`--out`で出力フォルダーを変更します（既定は`ui-refiner-scan/`）。

Claude Codeでは`/ui-review <URL>`コマンドひとつで、スキャン、スクリーンショットの確認、レビュー作成まで行います（[エージェントと使う](#エージェントと使う)参照）。

## `scan`の出力

`ui-refiner-scan/`に保存します（`--out`で変更可）。

| ファイル | 内容 |
|---|---|
| `DESIGN_REVIEW.md` | AI感指数、サインごとの根拠・理由・改善案、基本品質の表、日本語タイポグラフィ（日本語ページ）、ソース検査（`--source`）、避けられていたもの、エージェントの次の手順 |
| `scan.json` | 同じ内容の機械可読データ |
| `scan-desktop.png`、`scan-mobile.png` | 遅延読み込みまでスクロールした後の1440px・390pxの全体スクリーンショット |
| `before-scan-*.png`、`previous-scan.json` | 再スキャン時、並べて確認するために保存した前回のスクリーンショットと結果 |

### 修正前後の比較

同じページを同じフォルダーに再スキャンすると自動で比較します。フォルダーを分ける場合は`--compare`で前回のフォルダーを指定します。

```sh
ui-refiner scan localhost:5173                                   # 最初のスキャン
# … ページを修正 …
ui-refiner scan localhost:5173                                   # 最初のスキャンと自動で比較
ui-refiner scan localhost:5173 --out scan-after --compare scan-before
```

レポートの先頭に比較の節が付きます。AI感指数の変化、解消・新規・残っているサイン（強くなったか弱くなったか）、ルールごとの基本品質の変化、日本語組版の変化、前後のスクリーンショットへのリンクを示します。パスが同じなら比較できるので、本番サイトとローカル開発サーバーの比較も可能です。別のページやブラウザのロケールが異なる場合は警告を出します。例として`examples/ai-slop-landing-ja.html` → `examples/redesign-landing-ja.html`は100 → 0、サイン13件と日本語の問題7件が解消します。

## 日本語タイポグラフィのチェック

ページの大部分が日本語の場合、レポートに**日本語タイポグラフィ**の節が加わります。ブラウザで実際に描画された結果を計測するため、CSSフレームワークやビルド方法に依存しません。

| チェック | 重要度 | 何を見るか・なぜ問題か | 改善の方向 |
|---|---|---|---|
| 和文書体が指定されていない | 高 | font-familyに日本語グリフを持つ書体がない。OSごとに別のフォールバック書体で表示される。AI生成の`Inter, sans-serif`で頻発 | `Inter, "Noto Sans JP", "Hiragino Sans", "Yu Gothic UI", sans-serif`のように和文書体を明示 |
| 本文の行間が狭い | 中 | 40文字以上の段落でline-height 1.45未満。和文は字面が大きく詰まって見える | 本文1.7〜2.0、見出し1.3〜1.5 |
| 見出しの泣き別れ | 中/低 | 見出しの最終行が1〜2文字だけ。デスクトップとモバイルで別々に判定 | `word-break: auto-phrase`（Chrome）、BudouX、`<wbr>`で文節改行し、`text-wrap: balance` |
| 不自然な改行 | 中/低 | 大きな見出しの行頭が小書きの仮名や「ー」、または短いナビ・ボタンのラベル内での改行。ニュース一覧の改行は件数だけ数える | ラベルは`white-space: nowrap`か幅の調整、見出しは文節改行 |
| 見出しの`word-break: break-all` | 中 | 文節を無視して任意の位置で改行される | 見出しは`auto-phrase`か`keep-all`＋`<wbr>`。`break-all`はURLなど長い英数字だけに |
| 日本語の斜体 | 中 | 和文書体に斜体はなく、ブラウザが機械的に傾ける | 強調は太さ・色・傍点（`text-emphasis`）で |
| 字間の詰めすぎ | 低 | 欧文向けの負の字間（tracking-tight）で文字がぶつかる | 0〜0.05em。詰めるなら`font-feature-settings: "palt"`で約物だけ |
| 12px未満の日本語 | 低 | 画数の多い漢字が潰れる（フッター・注記は除外） | 最小12px、本文15〜16px以上 |
| 半角カナ・全角英数字 | 低 | 古いシステムの印象。検索や読み上げにも不利 | 全角カナ・半角英数字に統一 |

日本のWebの慣習はAI感として扱いません。ヒラギノ・Noto Sans JP・游ゴシックの書体指定、ロゴを入れた小さな`h1`、情報密度の高いレイアウトは正常です。

節の最後には、上で示した**日本のサイトとの比較**の表が付きます。本文の文字サイズ、行間、見出し÷本文の比率、文字サイズの数、色相グループの数、中央揃え・角丸のボックスの割合、コントラスト不足の要素数を比較します。データと収集方法は[data/ja-reference/](../data/ja-reference/README.md)にあります。

### 日本語のAI感サイン

- **紋切り型のコピー**（2つ以上で検出）：可能性を解き放つ、シームレスな、次世代の、ワンランク上の、ビジネスを加速、未来を切り拓く、新たな価値を創造、誰でも簡単に、魔法のように、かつてない、想像を超える、オールインワン など。「次世代」「革新」のような単語単体ではなく、言い回しで判定します。
- **汎用CTAの繰り返し**：詳しく見る、詳細はこちら、もっと見る、続きを読む、今すぐ始める、無料で始める など。

## AI感指数（0〜100）

描画結果から計測したサインによるヒューリスティックです。強いサインは3、中程度は2、弱いサインは1の重みです。選ばれたWebフォントと実際の画像がそれぞれスコアを15%下げますが、サイン自体は一覧に残ります。*報告のみ*と書いたサインは、人が作ったサイトでもAIが作ったサイトと同じくらい出たため、レポートには載せますがスコアには加えません。何もブロックしません。

| サイン | 計測内容 |
|---|---|
| 紫・藍色のグラデーションヒーロー | 文字の背後の大きなグラデーションで、色の大半が紫・藍・ピンク |
| 広い面積のグラデーション | 文字のある広い面を覆うグラデーション |
| グラデーション文字 | `background-clip: text`のグラデーション。見出しなら強いサイン |
| すりガラス | `backdrop-filter: blur`の箱の繰り返し（固定ナビゲーションは除外） |
| グロー | 色のついたぼかし影 |
| 絵文字アイコン | 単独または先頭に置かれたアイコン用の絵文字（ユーザー投稿内の絵文字は除外） |
| アイコンカードの並び | 1行に並ぶ同じ角丸カード3〜4枚（見出し＋説明） |
| 見出し上のピル型バッジ | ヘッドライン直上のバッジ |
| 中央揃え | ほとんどの段落が中央揃え |
| 角丸の多用 | ほぼすべての箱が16px以上の角丸 |
| カードの中のカード | 角丸の箱の中の角丸の箱。外側のカード3枚以上で |
| 角丸の四角に入ったアイコン | アイコンだけが入った、色付きの小さな角丸の四角が3つ以上 |
| 個性のない書体 | Inter・Roboto・システム書体ひとつで全部（日本語ページで和文書体の指定があれば除外） |
| 平坦なサイズ階層 | 最大の見出しが本文の2倍未満（日本語ページでは判定しない） |
| 既定のアクセントカラー | 手を加えていないTailwindのindigo/violet/purple（素の青とBootstrapの青は報告のみ） |
| 色数が多い | UIの有彩色が5系統以上 |
| 字間を広げたラベル | セクションごとに繰り返される、小さく字間を広げた大文字のラベル |
| 番号付きラベル | 「01 / …」「STEP 1 · …」のようなセクションラベル |
| 句点で終わる見出し | 句点（ピリオド）で終わる短い大見出し（"Stay by the sea."） |
| 紙色と明朝・セリフ | 温かみのあるオフホワイトの背景にセリフの大見出し。2025〜26年のエディトリアル風テンプレート |
| `transition: all` | 操作要素の計算済みスタイル（報告のみ） |
| 薄いオフホワイトの地色 | 純白ではなく薄いグレーやクリーム色の地。人が作ったサイトの約10%、AIサイトの25〜40%（報告のみ、`directions`で使用） |
| 紋切り型のコピー | 英語・韓国語・日本語の定型句が2つ以上 |
| 汎用CTAの繰り返し | 同じ汎用ボタン文言の繰り返し（報告のみ） |

装飾イラスト、`aria-hidden`の図、SVGの内部、固定ナビゲーションは除外し、作り込まれたブランド表現が誤検出されないようにしています。

### 基本品質

同梱のlintappleエンジンの共通ルールを描画済みページで計測します。文字のコントラスト、アクセシブルネーム、フォームラベル、ARIA参照、コントロールの状態、タップ領域、横はみ出し、ビューポート境界、フォント読み込みを確認します。書体・サイズ・文言などプロジェクト固有のルールは詳細ゲートで扱います。

### キャリブレーション

2026年11月の計測です（サイトの更新でスコアは変わります）。スクリプト：`scripts/calibrate-scan.mjs`、`scripts/rescore.mjs`。

| 集合 | サイト数 | 中央値 | 20点以上 |
|---|---:|---:|---:|
| ChatGPTで作られたサイト（調整用） | 30 | 38 | 70% |
| 人が作ったサイト（調整用） | 26 | 0 | 0% |
| Lovable/v0のサイト（検証用） | 38 | 28 | 68% |
| デザインスタジオ・受賞作・エディトリアルのサイト（検証用） | 29 | 5 | 3% |
| Replit/Lovableギャラリーのサイト（追加） | 77 | 35 | 74% |
| 韓国・グローバルブランド・報道・公共・個人のサイト（追加） | 54 | 8 | 15% |
| 日本の参照サイト | 210 | 0 | 1% |
| `examples/ai-slop-landing.html`、`ai-slop-landing-ja.html` | 2 | 100 | |

追加セット（`scripts/calibration-extra.tsv`）は基準を決めた後に加えました。スコアがいちばん弱いのはこのセットの人のサイト側です。toss.im、shopify.com、loom.com、canva.com、dropbox.comのような大手SaaS・消費者ブランドは、紫のグラデーション、紋切り型のコピー、カードの並び、すりガラスを同じように使うため27〜57点になります。スコアが低くても良いデザインの証明にはなりません。AIが作ったサイトの約3分の1は、まだ20点未満です。

## エージェントと使う

[skills/ui-refiner-agent/SKILL.md](../skills/ui-refiner-agent/SKILL.md)のスキルが2つの手順を定めます。

- **点検**：`scan`を実行し、まずスクリーンショットを見てから各サインの妥当性を判断する。結論、根本原因2〜3個、原因ごとのリデザイン方針（守るべきものを含む）、ユーザーが実際に困る品質問題を報告する。
- **直す（refine）**：スキャンし、守るべきものを書き出し、ファーストビューの案を3つ作って選んでもらい（`ui-refiner directions <フォルダー>`でスクリーンショットを並べて表示）、実際のコンテンツから固有の要素を加えて、根本原因ごとに直す。まず構成を見る（ピル型バッジ、2色の見出し、ロゴ名の列、アイコンカード、数字3つ、お客様の声3つ、料金3段、FAQ、CTA帯という定型の並び）。事実を作らず、別の定型スタイルに置き換えず、残るサインが意図したものになるまで再スキャンする（最大3回）。
- **作る**：プロジェクトと同梱のsutaガイドを読み、マークアップの前にデザイン方針を決め、既定値の罠を避ける。その後、開発サーバーを`scan`して意図しないものを直す（最大2回）。日本語UIでは和文書体の指定、行間、見出しの改行位置を必ず確認する。

インストールしておけば、CLIを自分で使う場面はほとんどありません。言葉で頼むか（「example.co.jpのデザインを点検して」「AIっぽくないLPを作って」「指摘を直してもう一度比較して」）、Claude Codeならスラッシュコマンドを使います。

```
/ui-review https://example.co.jp
/ui-review localhost:5173 強いサインを直して再スキャンして
/ui-refine landing.html
```

インストール方法：

| エージェント | 方法 |
|---|---|
| Claude Code（プラグイン） | `/plugin marketplace add prentice7725/ui-refiner`のあと`ui-refiner`をインストール。プラグインのフォルダーで`npm ci && npx playwright install chromium`を一度実行 |
| Claude Code / Codex（プロジェクト単位） | アプリの`tools/ui-refiner`にこのリポジトリを置き、`node tools/ui-refiner/scripts/install-agent-skill.mjs .`を実行。`.claude/skills/ui-refiner-agent`と`/ui-review`コマンド（Claude Code）、`.agents/skills/ui-refiner-agent`（Codex）にスキルを置き、編集後フックを登録 |

同梱のデザイン知識は`vendor/suta/skills/suta`（韓国語）にあります。AIスロップの禁止ライン、レイアウト・モーションの値、テスト済みUIパターン57種です。

## 詳細QAゲート（任意）

開発やCIで強制ゲートが必要なプロジェクトでは、`init`＋`check`でプロジェクトのポリシーに沿ってsutaの静的検査とlintappleの描画検査を実行します。ルート、操作状態、ベースライン、変更行スコープ、証拠画像、ARIA比較、ビジュアルリグレッション、SARIF/HTMLエクスポート、レビューパケットに対応します。

```sh
node tools/ui-refiner/bin/ui-refiner.mjs init --dir "$PWD" --locale ja-JP
node tools/ui-refiner/bin/ui-refiner.mjs check --config ui-refiner.config.json
```

`--locale ja-JP`の初期ポリシーには、ヒラギノ・Noto Sans JP・メイリオ・游ゴシックなどの和文書体と日本語の禁止文言が入ります。終了コード：0 合格（人の確認が残る場合あり）、1 違反、2 エラーまたは検査範囲の不足、3 部分範囲のみ合格。既定ポリシーは承認済みの書体だけを許可するので、強制する前に`ui-policy.json`をプロジェクトのタイポグラフィに合わせてください。

詳しい説明：[docs/gate/README_JA.md](gate/README_JA.md) · [English](gate/README.md) · [한국어](gate/README_KO.md)。エージェントの手順：[reference/quality-gate.md](../skills/ui-refiner-agent/reference/quality-gate.md)。

## 制限

- `scan`はビューポートごとに読み込み直後の状態を1つだけ見ます。操作後の状態、ログインが必要なページ、アプリ全体の一貫性は詳細ゲートか人の確認が必要です。
- 指数はヒューリスティックであり、センスの判定ではありません。スコアが低くても良いデザインとは限らず、意図したブランドのグラデーションは問題ありません。最終的な見た目の承認は人が行います。
- ビジョンモデルは呼び出しません。見た目の判断はスクリーンショットを読むエージェントが行います。
- Canvasアプリ、Godot・PhaserのUI、ゲームHUDは対象外です。
- スクリーンショットとレポートにはページの内容が含まれます。共有前に確認してください。

## 開発

```sh
npm test                 # ユニットテスト
npm run smoke:scan       # 実ブラウザ：英語・日本語のスロップ見本とデモの比較
npm run smoke:ui         # その他のスモーク：smoke:gate、smoke:routes、smoke:visual …
```

CIですべてのテストを実行します（[.github/workflows/ci.yml](../.github/workflows/ci.yml)）。同梱エンジンは固定バージョンとハッシュで検証しています（[vendor/UPSTREAM.json](../vendor/UPSTREAM.json)）。変更点は[CHANGELOG.md](../CHANGELOG.md)、背景調査は[docs/](./)にあります。
