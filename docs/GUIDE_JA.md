## クイックスタート

必要環境：Node.js 22.18 以上、npm、Git。

```sh
git clone https://github.com/prentice7725/ui-refiner && cd ui-refiner
npm ci && npx playwright install chromium
npm link                                   # 任意：どこからでも `ui-refiner` で実行できるようにする

ui-refiner scan your-site.example          # 公開中のページを点検
ui-refiner scan localhost:5173             # 開発サーバー。修正後に同じコマンドを再実行すると変化が分かる
ui-refiner keep record index.html                                  # リファイン前にリンク・フォーム・数値を記録
ui-refiner directions deal refine-directions --kind service --tone calm --lang ja   # 3つのレーン（familiar・tailored・bold）にヒーロー構成、各レーンの要素（地色・色系統・マテリアル）、避ける書体を割り当て
ui-refiner directions refine-directions     # デザイン案（.html）を並べて比較し、1つ選ぶ
ui-refiner directions record refine-directions --pick B                # 選んだ方針を記録（別のクライアントには別の方針）
ui-refiner theme starter care-white --brand "#0b5cab"           # 実測テーマのファイルと brand.css を書き出し、必要な写真とブランド色で崩れたコントラストを一覧
ui-refiner photos "dentist chair" --out assets/stand-in             # 実際の写真が届くまでの出典付き仮写真（Wikimedia Commons）
ui-refiner directions verify refine-directions index.html             # 仕上がりが選んだ構成を保っているか確認
ui-refiner system extract index.html                                  # 選んだデザインをサイトの他のページ用に保存
ui-refiner system check about.html pricing.html                       # 他のページがそのデザインを保っているか確認
ui-refiner keep check index.html                                   # リファイン後のページで記録項目のうち1つでも失われたら exit 1
ui-refiner stress index.html                                       # 長いラベル・メール・電話番号・大きな数字を入れて 320/390/1440px で確認、崩れたら exit 1
ui-refiner prefer add surface paper --said "クリーム色の背景はもうやめて"   # この人が望まないもの。以後の割り当てから除外
```

手順はこれだけです。`scan` は URL、ホスト名、ローカルの `.html` ファイルを受け付け、設定は不要で、対象プロジェクトを変更しません。`npm link` をしていない場合は `node bin/ui-refiner.mjs scan …` で実行します。

日本や韓国のサイトを実測したデザインから始めるには、[skills/ui-refiner-agent/reference/themes](../skills/ui-refiner-agent/reference/themes/README.md) の 14 テーマから 1 つを選び、エージェントにそのテーマで作るよう依頼してください。テーマごとに実測の根拠、トークン、セクション構成、CSS、サンプルページがあります。

- **レポートの言語**はページに合わせます。日本語ページは日本語、韓国語ページは韓国語、それ以外は英語です。常に同じ言語にしたい場合は `UI_REFINER_LANG=ja`（または `ko`、`en`）を設定し、1 回だけ変えるなら `--lang` を使います。ブラウザのロケールはホストに合わせます（`.jp` → `ja-JP`、`.kr` → `ko-KR`）。`--locale` で変更できます。
- **再スキャンすると自動で比較します。** 出力フォルダに同じページの前回スキャンがあれば、新しいレポートの先頭に前後比較が付きます。比較しない場合は `--no-compare`、別フォルダのスキャンと比べる場合は `--compare <フォルダ>` を使います。
- `--source src` でソースの静的検査を追加し、`--out` で出力フォルダを変更します（既定は `ui-refiner-scan/`）。

Claude Code では `/ui-review <URL>` コマンドひとつで、スキャン、スクリーンショットの確認、レビュー作成まで進みます（[エージェントと使う](#エージェントと使う)参照）。

## `scan` の出力

出力先は `ui-refiner-scan/` です（`--out` で変更可）。

| ファイル | 内容 |
|---|---|
| `DESIGN_REVIEW.md` | AI 感指数、サインごとの根拠・理由・改善案、基本品質の表、日本語タイポグラフィ（日本語ページ）、ソース検査（`--source`）、避けられていたもの、エージェントの次の手順 |
| `scan.json` | 同じ内容の機械可読データ |
| `scan-desktop.png`、`scan-mobile.png` | 遅延読み込みまでスクロールした後の 1440px・390px の全体スクリーンショット |
| `before-scan-*.png`、`previous-scan.json` | 再スキャン時に並べて確認するために保存した前回のスクリーンショットと結果 |

### 修正前後の比較

同じページを同じフォルダに再スキャンすると自動で比較します。フォルダを分ける場合は `--compare` で前回のフォルダを指定してください。

```sh
ui-refiner scan localhost:5173                                   # 最初のスキャン
# … ページを修正 …
ui-refiner scan localhost:5173                                   # 最初のスキャンと自動で比較
ui-refiner scan localhost:5173 --out scan-after --compare scan-before
```

レポートの先頭に比較の節が付き、AI 感指数の変化（`前 → 後`）、解消・新規・残存サイン（強くなったか弱くなったかを含む）、ルールごとの基本品質の変化、日本語組版の変化、前後のスクリーンショットへのリンクを示します。パスが同じであれば比較できるため、本番サイトとローカル開発サーバーの比較も可能です。別のページや異なるブラウザロケールの場合は警告を出します。例として `examples/ai-slop-landing-ja.html` → `examples/redesign-landing-ja.html` では `100 → 0` になり、サイン 13 件と日本語の問題 7 件が解消します。

### 日本語ページ（日本語）

ページの大部分が日本語の場合、レポートに **日本語タイポグラフィ** の節が加わります。ブラウザで実際に描画された結果を計測するため、CSS フレームワークやビルド方法に依存しません。

| チェック | 重要度 | 何を見るか・なぜ問題か | 改善の方向 |
|---|---|---|---|
| 和文書体が指定されていない | 高 | `font-family` に日本語グリフを持つ書体がない。OS ごとに別のフォールバック書体で表示される。AI 生成の `Inter, sans-serif` で頻発 | `Inter, "Noto Sans JP", "Hiragino Sans", "Yu Gothic UI", sans-serif` のように和文書体を明示 |
| 本文の行間が狭い | 中 | 40 文字以上の段落で `line-height` 1.45 未満。和文は字面が大きく詰まって見える | 本文 1.7〜2.0、見出し 1.3〜1.5 |
| 見出しの泣き別れ | 中/低 | 見出しの最終行が 1〜2 文字だけになる。デスクトップとモバイルで別々に判定 | `word-break: auto-phrase`（Chrome）、BudouX、`<wbr>` で文節改行し、`text-wrap: balance` を併用 |
| 不自然な改行 | 中/低 | 大きな見出しの行頭が小書きの仮名や「ー」、または短いナビ・ボタンのラベル内で改行される（ニュース一覧の改行は件数のみ集計） | ラベルは `white-space: nowrap` か幅の調整、見出しは文節改行 |
| 見出しの `word-break: break-all` | 中 | 文節を無視して任意の位置で改行される | 見出しは `auto-phrase` か `keep-all` ＋ `<wbr>`。`break-all` は URL など長い英数字のみに限定 |
| 日本語の斜体 | 中 | 和文書体に斜体はなく、ブラウザが機械的に傾けて表示する | 強調は太さ・色・傍点（`text-emphasis`）で表現 |
| 字間の詰めすぎ | 低 | 欧文向けの負の字間（`tracking-tight`）で文字同士がぶつかる | `0〜0.05em`。詰める場合は `font-feature-settings: "palt"` で約物のみ調整 |
| 12px 未満の日本語 | 低 | 画数の多い漢字が潰れる（フッター・注記は除外） | 最小 12px、本文 15〜16px 以上 |
| 半角カナ・全角英数字 | 低 | 古いシステムの印象を与え、検索や読み上げにも不利 | 全角カナ・半角英数字に統一 |

日本の Web の慣習は AI 感として扱いません。ヒラギノ・Noto Sans JP・游ゴシックの書体指定、ロゴを入れた小さな `h1`、情報密度の高いレイアウトは正常とみなします。

節の最後には、日本の実測サイトと比較する **日本のサイトとの比較** の表が付きます。本文の文字サイズ、行間、見出しと本文の比率、文字サイズの数、色相グループの数、中央揃え・角丸ボックスの割合、コントラスト不足の要素数を比較します。データと収集方法は [data/ja-reference/](../data/ja-reference/README.md) にあります。

#### 日本語の AI 感サイン

- **紋切り型のコピー**（2 つ以上で検出）：可能性を解き放つ、シームレスな、次世代の、ワンランク上の、ビジネスを加速、未来を切り拓く、新たな価値を創造、誰でも簡単に、魔法のように、かつてない、想像を超える、オールインワン など。「次世代」「革新」のような単語単体ではなく、言い回しで判定します。
- **汎用 CTA の繰り返し**：詳しく見る、詳細はこちら、もっと見る、続きを読む、今すぐ始める、無料で始める など。

### AI 感指数（0〜100）

描画結果から計測したサインによるヒューリスティックです。強いサインは 3、中程度は 2、弱いサインは 1 の重みで加算します。選ばれた Web フォントと実際の画像がそれぞれスコアを 15% 下げますが、サイン自体は一覧に残ります。*報告のみ*と記したサインは、人が作ったサイトでも AI が作ったサイトと同じくらい見られたため、レポートには載せますがスコアには加えません。また、この指数が処理をブロックすることはありません。

| サイン | 計測内容 |
|---|---|
| 紫・藍色のグラデーションヒーロー | 文字の背後にある大きなグラデーションで、色の大半が紫・藍・ピンク |
| 広い面積のグラデーション | 文字のある広い面を覆うグラデーション |
| グラデーション文字 | `background-clip: text` のグラデーション（見出しなら強いサイン） |
| すりガラス | `backdrop-filter: blur` を用いたボックスの繰り返し（固定ナビゲーションは除外） |
| グロー | 色のついたぼかし影 |
| 絵文字アイコン | 単独または先頭に置かれたアイコン用の絵文字（ユーザー投稿内の絵文字は除外） |
| アイコンカードの並び | 1 行に並ぶ同じ角丸カード 3〜4 枚（見出し＋説明） |
| 見出し上のピル型バッジ | ヘッドライン直上のピル型バッジ |
| 中央揃え | ほとんどの段落が中央揃え |
| 角丸の多用 | ほぼすべてのボックスが 16px 以上の角丸 |
| カードの中のカード | 外側のカード 3 枚以上で、角丸の箱の中に角丸の箱が入れ子になっている |
| 角丸の四角に入ったアイコン | アイコンだけが入った色付きの小さな角丸の四角が 3 つ以上 |
| 個性のない書体 | Inter・Roboto・システム書体の 1 つだけで全体を組んでいる（日本語ページで和文書体の指定があれば除外） |
| 平坦なサイズ階層 | 最大の見出しが本文の 2 倍未満（日本語ページでは判定しない。報告のみ：英語圏の人のサイトの 19%、AI サイトの 8% で出現） |
| 既定のアクセントカラー | 手を加えていない Tailwind の indigo/violet/purple（素の青と Bootstrap の青は報告のみ） |
| 色数が多い | UI の有彩色が 5 系統以上 |
| 字間を広げたラベル | セクションごとに繰り返される、小さく字間を広げた大文字のラベル |
| 番号付きラベル | 「01 / …」「STEP 1 · …」のようなセクションラベル |
| 句点で終わる見出し | ピリオドで終わる短い大見出し（`"Stay by the sea."`） |
| 紙色と明朝・セリフ | 温かみのあるオフホワイトの背景にセリフ・明朝の大見出し（2025〜26 年のエディトリアル風テンプレート） |
| `transition: all` | 操作要素の計算済みスタイル（報告のみ） |
| 薄いオフホワイトの地色 | 純白ではなく薄いグレーやクリーム色の地（人が作ったサイトの約 10%、AI サイトの 25〜40%。報告のみで `directions` が活用） |
| 紋切り型のコピー | 英語・韓国語・日本語の定型句が 2 つ以上（報告のみ：英語圏の人のサイトの 14%、AI サイトの 13% で出現） |
| 汎用 CTA の繰り返し | 同じ汎用ボタン文言の繰り返し（報告のみ） |

装飾イラスト、`aria-hidden` の図、SVG の内部、固定ナビゲーションは除外し、作り込まれたブランド表現が誤検出されないようにしています。

### 基本品質

同梱の `lintapple` エンジンの共通ルールを描画済みページで計測します。文字のコントラスト、アクセシブルネーム、フォームラベル、ARIA 参照、コントロールの状態、タップ領域、横はみ出し、ビューポート境界、フォント読み込みを確認します。書体・サイズ・文言などプロジェクト固有のルールは詳細ゲートで扱います。

ページに残った仮の値（`placeholder-text`）も一覧表示します。0 で埋めた電話番号や郵便番号（`031-000-0000`、`〒530-0000`）、住所の「○○町」「OO구」、「Lorem ipsum」、「[会社名]」、`@example.com` のアドレスが対象です。これは AI 感のサインではなく品質の項目です。Claude と Codex が 1 行の依頼で作った日本語・韓国語のページ 79 件のうち 35 件、人が作った日本・韓国のサイト 1,845 件のうち 2 件で見つかりましたが、モデルの書き癖ではなく、事実を渡さずに作ったことから生じるためです。

Vercel の Web Interface Guidelines から取り入れた 3 つのルールも同じように扱います。拡大を止める viewport の meta（`zoom-disabled`）、スマートフォンで 16px 未満のためフォーカス時に iOS Safari が画面を拡大してしまう入力欄（`input-zoom`）、貼り付けを拒む入力欄（`paste-blocked`）です。人が作った日本・韓国のサイト 60 件のうち 13 件が拡大を止め、9 件に小さい入力欄があったため、AI 感のサインではなく品質の項目としています。

### キャリブレーション

2026 年 11 月 19 日に現在の採点方法で測り直しました（サイトの更新でスコアは変わり、応答しなくなったサイトがあるため集合の大きさが少し変わりました）。スクリプト：`scripts/calibrate-scan.mjs`、`scripts/rescore.mjs`。

| 集合 | サイト数 | 中央値 | 20 点以上 |
|---|---:|---:|---:|
| ChatGPT で作られたサイト（調整用） | 30 | 38 | 70% |
| 人が作ったサイト（調整用） | 26 | 0 | 0% |
| Lovable/v0 のサイト（検証用） | 39 | 31 | 69% |
| デザインスタジオ・受賞作・エディトリアルのサイト（検証用） | 29 | 0 | 0% |
| Replit/Lovable ギャラリーのサイト（追加） | 76 | 33 | 74% |
| 韓国・グローバルブランド・報道・公共・個人のサイト（追加） | 55 | 4 | 9% |
| 業種別の韓国の人が作ったサイト（`data/genre-reference`） | 776 | 0 | 7% |
| 業種別の日本の人が作ったサイト（`data/genre-reference`） | 1014 | 0 | 3% |
| Claude Opus 5.5 が 1 行の依頼で作った日本語・韓国語のページ（`scripts/calibration-ai-krjp.tsv`、ベンチマーク 7 件を含む） | 43 | 33 | 81% |
| 同じ依頼を Codex（`gpt-6.2-sol`）で作ったページ | 36 | 24 | 64% |
| `examples/ai-slop-landing.html`、`ai-slop-landing-ja.html` | 2 | 100 | |

追加セット（`scripts/calibration-extra.tsv`）は基準を決めた後に加えました。スコアがいちばん弱いのはこのセットの人のサイト側です。`toss.im`、`shopify.com`、`allbirds.com`、`loom.com` のような大手 SaaS・消費者ブランドは、紫のグラデーション、カードの並び、すりガラスを同じように使うため 27〜38 点になります。業種別の韓国のサイトで誤って引っかかるのは、詰まったバナー、ポップアップ、カードの並び、グラデーション、絵文字、すりガラスといった韓国の商業サイトの作り方によるものです。

日本語・韓国語の AI ページは、2026 年 11 月 19 日に 1 行の依頼 36 件（日本語 18、韓国語 18）を 2 つのツールで 1 回ずつ作ったものです。Codex には組み込みのスキルだけが見えるようにしました。韓国語のページ（77%）のほうが日本語のページ（70%）より検出されやすくなっています。2026 年 11 月 20 日からは、日本語・韓国語のページでもクリーム色の背景にセリフ・明朝の見出し（`paper-serif`）を強いサインとして数えています。これらの AI ページの 44〜50%、人が作った日本・韓国のサイトの 0.5〜1.5% に見られ、強いサインにすると 79 ページのうち 7 件を新たに検出しました（`65% → 73%`）。人のサイトでは、19 点だった日本のサイト 3 件が 20 点になりました。

まだ 20 点未満の Codex のページは、多くが点数の付くサインを持ちません。淡いセージ色の背景、右半分の写真、ダッシュで始まる小さなラベル、ヒーロー下のアイコン付きカードの列ですが、これを見るサインはまだありません。報告のみだった 2 つのサイン（見出しの 1 語だけ色を変える、うっすら色の付いた背景）を日本語・韓国語のページで採点する案も試しましたが、採用しませんでした。別に取っておいた依頼 12 件では 24 件中 1 件多く検出しただけで、人が作った日本・韓国のサイトで 20 点以上になる割合が約 1 ポイント増えるためです。スコアが低くても良いデザインの証明にはならず、AI が作ったサイトの 4 分の 1 以上は、まだ 20 点未満です。

## エージェントと使う

[skills/ui-refiner-agent/SKILL.md](../skills/ui-refiner-agent/SKILL.md) のスキルは 3 つの手順を定めています。

- **点検**：`scan` を実行し、まずスクリーンショットを見てから各サインの妥当性を判断します。結論、根本原因 2〜3 個、原因ごとのリデザイン方針（守るべきものを含む）、ユーザーが実際に困る品質問題を報告します。
- **直す（refine）**：スキャンして守るべきものを書き出し、ファーストビューの案を 3 つ作って選んでもらいます（`ui-refiner directions <フォルダ>` でスクリーンショットを並べて表示）。実際のコンテンツから固有の要素を加えて、根本原因ごとに直します。まず構成を見ます（ピル型バッジ、2 色の見出し、ロゴ名の列、アイコンカード、数字 3 つ、お客様の声 3 つ、料金 3 段、FAQ、CTA 帯という定型の並び）。事実を作らず、別の定型スタイルに置き換えず、残るサインが意図したものになるまで再スキャンします（最大 3 回）。
- **作る**：プロジェクトと同梱の `suta` ガイドを読み、マークアップの前にデザイン方針を決めて既定値の罠を避けます。その後、開発サーバーを `scan` して意図しないものを直します（最大 2 回）。日本語 UI では和文書体の指定、行間、見出しの改行位置を必ず確認します。

インストールしておけば、CLI を自分で使う場面はほとんどありません。言葉で頼むか（「example.co.jp のデザインを点検して」「AI っぽくない LP を作って」「指摘を直してもう一度比較して」）、Claude Code ならスラッシュコマンドを使います。

```
/ui-review https://example.co.jp
/ui-review localhost:5173 強いサインを直して再スキャンして
/ui-refine landing.html
```

インストール方法：

| エージェント | 方法 |

### Modern Web Guidance と併用する（任意）

UI Refiner はページの見た目を決めます。[Modern Web Guidance](https://github.com/GoogleChrome/modern-web-guidance) はページの作り方（ダイアログ、フォーム、画像、読み込み、アクセシビリティ）を扱う別のスキルです。併用するには「Modern Web Guidance を使って landing.html をリファインして」のように依頼するか、プロジェクトにインストールしておくと（`npx modern-web-guidance@latest install`）スキルが自動で参照します。既定ではオフです。3 ページで使った場合と使わない場合を比べたところ、アクセシビリティとベストプラクティスのスコアは同じでした。

## 詳細 QA ゲート（任意）

開発や CI で強制ゲートが必要なプロジェクトでは、`init` ＋ `check` でプロジェクトのポリシーに沿って `suta` の静的検査と `lintapple` の描画検査を実行します。ルート、操作状態、ベースライン、変更行スコープ、証拠画像、ARIA 比較、ビジュアルリグレッション、SARIF/HTML エクスポート、レビューパケットに対応します。

```sh
node tools/ui-refiner/bin/ui-refiner.mjs init --dir "$PWD" --locale ja-JP
node tools/ui-refiner/bin/ui-refiner.mjs check --config ui-refiner.config.json
```

`--locale ja-JP` の初期ポリシーには、ヒラギノ・Noto Sans JP・メイリオ・游ゴシックなどの和文書体と日本語の禁止文言が入ります。終了コード：`0` 合格（人の確認が残る場合あり）、`1` 違反、`2` エラーまたは検査範囲の不足、`3` 部分範囲のみ合格。既定ポリシーは承認済みの書体だけを許可するため、強制する前に `ui-policy.json` をプロジェクトのタイポグラフィに合わせてください。

詳しい説明：[docs/gate/README_JA.md](gate/README_JA.md) · [English](gate/README.md) · [한국어](gate/README_KO.md)。エージェントの手順：[reference/quality-gate.md](../skills/ui-refiner-agent/reference/quality-gate.md)。

## 制限

- `scan` はビューポートごとに読み込み直後の状態を 1 つだけ見ます。操作後の状態、ログインが必要なページ、アプリ全体の一貫性は詳細ゲートか人の確認が必要です。
- 指数はヒューリスティックであり、センスの判定ではありません。スコアが低くても良いデザインとは限らず、意図したブランドのグラデーションは問題ありません。最終的な見た目の承認は人が行います。
- ビジョンモデルは呼び出しません。見た目の判断はスクリーンショットを読むエージェントが行います。
- Canvas アプリ、Godot・Phaser の UI、ゲーム HUD は対象外です。
- スクリーンショットとレポートにはページの内容が含まれます。共有前に確認してください。
