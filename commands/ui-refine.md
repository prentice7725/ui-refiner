Refine the page: $ARGUMENTS

Follow the **Refine** workflow of the `ui-refiner-agent` skill:

1. Find the source that renders the target (the `.html` file itself, or the project files behind the dev server). If you cannot edit it, stop and run the **Review** workflow instead.
2. Run `node <UI_REFINER>/bin/ui-refiner.mjs scan <target>` (the skill explains where `<UI_REFINER>` is), then open `ui-refiner-scan/scan-desktop.png` and `scan-mobile.png` before reading `DESIGN_REVIEW.md`.
3. Write down what must be preserved and record it with `node <UI_REFINER>/bin/ui-refiner.mjs keep record <target>`. Then run `node <UI_REFINER>/bin/ui-refiner.mjs directions deal refine-directions --kind <software|service|place|public|company|studio|media> --lang <page language>` (with `--no-photo` when there are no real photos and stand-ins do not fit; otherwise fetch credited stand-ins with `node <UI_REFINER>/bin/ui-refiner.mjs photos "<subject>" --out assets/stand-in`, mark them `data-stand-in`, keep the credit line in the footer and tell the user to replace them). It deals each direction a hero structure and a surface and lists faces to avoid. Choose the type yourself: one strong display face per direction, picked for this subject and kept through the page. Write each headline from a fact only this client has (an hour, a condition, a number, a place), never a category slogan. Mock the first screen in `refine-directions/a.html`, `b.html` and `c.html`, each built from its deal (a real brand surface overrides it) and each with a signature element only this subject would have, built from real content. Give the first screen one main piece (photo, product screen or signature element), not all of them stacked. Use only stand-in photos of this kind of place or work, never generic office objects. Use at most one faint off-white surface. Whatever the structure, each first screen says what this is in one line and shows the main action above the fold. Without photos, no other text dwarfs that line; a signature element supports the claim beside or below it, never in larger type. Each first screen also shows something real: photos (real or stand-in) for places and services, or for software a large finished product screen built in code and marked `data-product-shot` (a quarter of the screen or more, text 12px or larger). Never the dark dashboard template (near-black or navy ground, metric-card rows, neon lime or electric blue accent): judges read it as crypto or dev-tool. If the sheet notes a run of white picks, prefer the dealt non-white direction unless the brand calls for white.
   Run `node <UI_REFINER>/bin/ui-refiner.mjs directions refine-directions`. If the sheet warns, redo that mock first.
   Show the user the three directions, the `DIRECTIONS.html` path and your recommendation, then stop and ask which to apply (mixing is allowed). Decide yourself only if the extra instructions say so.
   Record the choice with `node <UI_REFINER>/bin/ui-refiner.mjs directions record refine-directions --pick <A|B|C> --page <name>`.
4. Apply the direction by root cause: structure, type, color and surface, copy. Do not invent facts, and do not swap in another stock look. Removing the tells is not enough: a page that is only plainer is not done.
5. Run `node <UI_REFINER>/bin/ui-refiner.mjs keep check <target>` and restore anything lost or changed; never round, update or invent a figure. Run `node <UI_REFINER>/bin/ui-refiner.mjs directions verify refine-directions <target>`. If it reports drift from the chosen hero structure, surface or type, or a first screen without a claim or main action, or a claim dwarfed by other text, or no photo or product screen, fix the page first. Then rerun the same scan command. The report opens with the before/after comparison. Check the craft list in the skill against the screenshots; the score is only a guard. Repeat at most three rounds.
6. Reply in the user's language with: the chosen direction, the signature element, score before → after, resolved and remaining signals with reasons, the changes by root cause, what was preserved, and the screenshot paths.
