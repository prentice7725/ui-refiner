Refine the page: $ARGUMENTS

If the page was already refined and the extra instructions only ask for it bolder or quieter (as a whole, or one named section), follow **Bolder or quieter** in the `ui-refiner-agent` skill (`reference/steer.md`) instead of the steps below.

Otherwise follow the **Refine** workflow of the `ui-refiner-agent` skill. If the extra instructions ask for Modern Web Guidance, or the project already has it installed, also follow **Optional: Modern Web Guidance** in the skill while you build.

1. Find the source that renders the target (the `.html` file itself, or the project files behind the dev server). If you cannot edit it, stop and run the **Review** workflow instead.
2. Run `node <UI_REFINER>/bin/ui-refiner.mjs scan <target>` (the skill explains where `<UI_REFINER>` is), then open `ui-refiner-scan/scan-desktop.png` and `scan-mobile.png` before reading `DESIGN_REVIEW.md`. Decide how much to change from the score: 20 or more, the full refine below; 8–19, or any page with a real brand, polish it (keep structure, palette and type, fix the confirmed signals and craft issues, skip the directions, still run `keep record` and `keep check`); under 8 with no confirmed signal, report and change nothing unless asked.
3. Write down what must be preserved and record it with `node <UI_REFINER>/bin/ui-refiner.mjs keep record <target>`. Pick the page kind and the tone from who visits and why (calm: health, care, public, money; warm: local places, food, families, community; technical: tools for engineers and operations; bold: campaigns, youth brands, media). When the page leads with photos and has none, fetch credited stand-ins first with `node <UI_REFINER>/bin/ui-refiner.mjs photos "<subject>" --out assets/stand-in` and tell the user to replace them; otherwise pass `--no-photo` to the deal.
   **A Korean or Japanese trade page with no real brand starts from a theme instead of the directions below** (the skill's Refine section says when): fetch stand-ins first when it has no photographs, pick the theme from `skills/ui-refiner-agent/reference/themes/README.md` by country and purpose family, read its `theme.md`, `theme.css` and `sample.html`, and apply it to the page's own content as that README's "Applying a theme" says. Skip `directions deal`, `record` and `verify` and go on at step 5. Use the three directions only when the extra instructions ask for options or a look of the client's own, or when no theme fits.
   Run `node <UI_REFINER>/bin/ui-refiner.mjs directions deal refine-directions --kind <software|service|place|public|company|studio|media> --tone <calm|warm|technical|bold> --lang <page language>`; on a Korean or Japanese page add `--trade <trade>` when the client is one of the trades the skill lists (salon, inn, restaurant, academy and so on), so the familiar direction follows measured sites of that trade. It deals three directions built from three different sources: A familiar (what human-made sites of this kind do, as measured), B tailored (colour, type and look from this client's own content) and C bold (one material, a finished look taken from a physical thing). Each has a hero structure and a lane file.
   Build each direction in its own subagent, all three at once. Give each only the lane README and its own lane file to read, the page path, kind, tone and language, its own entry from `DEAL.json` with the faces to avoid, and the file to write (`refine-directions/a.html`, `b.html` or `c.html`: the first screen and one section). Do not tell one what the others are, and do not suggest a concept, a typeface, a palette or a signature element.
   Run `node <UI_REFINER>/bin/ui-refiner.mjs directions refine-directions`. If the sheet warns about a mock, send it back to a new subagent with its lane file and the warning only.
   Show the user the three directions by name (familiar, tailored, bold), the `DIRECTIONS.html` path and your recommendation, then stop and ask which to apply. Decide yourself only if the extra instructions say so.
   Record the choice with `node <UI_REFINER>/bin/ui-refiner.mjs directions record refine-directions --pick <A|B|C> --page <name>`.
4. Read the chosen direction's lane file (and the material's file for the bold direction), then apply the direction by root cause: structure, type, color and surface, copy. Keep its ground, colour, type and surfaces from the first screen to the footer. Do not invent facts, and do not swap in another stock look. Removing the tells is not enough: a page that is only plainer is not done.
5. Run `node <UI_REFINER>/bin/ui-refiner.mjs keep check <target>` and restore anything lost or changed; never round, update or invent a figure. When directions were dealt, run `node <UI_REFINER>/bin/ui-refiner.mjs directions verify refine-directions <target>`. If it reports drift from the chosen hero structure, surface or type, or a first screen without a claim or main action, or a claim dwarfed by other text, or no photo or product screen, fix the page first. Then rerun the same scan command. The report opens with the before/after comparison. For the bold direction, then run the finish review in fresh context (`reference/review.md`) and fix what is real. Check the craft list in the skill against the screenshots; the score is only a guard, and a signal the material's file calls for is deliberate. Repeat at most three rounds.
6. Once the page passes both checks, run `node <UI_REFINER>/bin/ui-refiner.mjs system extract <target>`. It writes `DESIGN_SYSTEM.md` next to the page, so the site's other pages can be built in the same design ("The site's other pages" in the skill).
7. Reply in the user's language with: the theme used (and that three directions are available on request), or the chosen direction (familiar, tailored or bold, and the material if bold), the signature element, the finish review's findings and their outcome if it ran, score and verdict before → after, resolved and remaining signals with reasons, the changes by root cause, what was preserved, and the screenshot paths.
